# 产品需求文档（PRD）

## 1. 文档信息

| 项目 | 内容 |
|---|---|
| 产品名称 | 企业项目管理平台（暂定） |
| 文档版本 | v0.1 |
| 产品阶段 | 需求草案 |
| 目标用户 | 企业内部用户与外部客户 |
| 预计规模 | 500 人以上 |
| 部署方式 | 私有化部署 |

## 2. 产品背景与目标

企业在内部项目、临时任务及客户交付过程中，存在项目进度不透明、跨部门责任难追踪、资源冲突难发现、交付验收记录分散等问题。

平台目标：

1. 统一管理需求、项目、里程碑、任务、工时、风险、文档、预算和验收。
2. 让管理者及时掌握项目进度、逾期情况、部门负荷和风险。
3. 支持项目经理直接调度跨部门成员，提高协作效率。
4. 为外部客户提供受限视图，只展示与其相关的需求、进度和文档。
5. 通过可配置流程、审批、状态权限、通知与升级机制规范项目执行。

## 3. 用户与角色

| 角色 | 核心诉求 |
|---|---|
| 管理员 | 系统配置、账号管理、全局治理、重复数据合并 |
| 项目经理 | 管理本项目全部日常作业、资源、进度、风险和交付 |
| 项目成员 | 执行任务、协作、更新进度、提交工时和文档 |
| 部门负责人 | 查看本部门成员、任务、负荷、逾期和工时 |
| 客户 | 提交需求、查看关联进度与文档、执行交付验收 |

## 4. 产品范围

### 4.1 项目与任务

- 层级采用：`项目 → 里程碑 → 任务 → 子任务`。
- 需求可以关联已有项目，也可以审批后创建新项目。
- 首期已确认项目类型：内部项目、临时任务。
- 每种项目类型拥有独立的流程模板和审批规则。
- 项目经理可以直接指定其他部门成员。
- 项目经理可以处理本项目全部作业，但客户专属验收动作按状态权限隔离。

### 4.2 任务字段

每项任务至少包含：

- 标题、描述、所属项目和里程碑
- 负责人、参与人
- 计划开始日期时间、计划截止日期时间
- 实际开始日期时间、实际完成日期时间
- 优先级、状态、预计工时、实际工时
- 创建人、创建时间、更新时间
- 附件、评论、操作记录

### 4.3 需求管理

需求来源包括：

- 登录系统填写动态表单
- 邮件自动转需求
- 企业微信入口
- 移动端提交

无法自动识别所属项目的邮件需求进入“待分派需求池”。管理员或授权人员为其指定负责人、项目类型与审批流程。

### 4.4 看板、甘特图与里程碑

- 看板按状态展示任务，状态列由项目模板配置。
- 甘特图展示项目、里程碑、任务与子任务的计划时间和实际时间。
- 里程碑展示负责人、目标日期、完成率与达成状态。
- 任务依赖、关键路径、基线和拖拽排期属于待确认范围。

### 4.5 状态与流程

默认任务状态：待处理、进行中、阻塞、待验收、已完成、已取消。

默认状态权限：

- 项目成员：开始、暂停/阻塞、提交完成。
- 项目经理：退回、取消、重新打开，并管理本项目其他状态。
- 客户：验收通过、驳回、要求修改。
- 管理员：处理全部状态；异常操作应记录审计信息。

状态、状态迁移、可操作角色、必填字段、审批节点及通知规则均需可配置。

### 4.6 审批

- 审批流程根据项目类型动态决定。
- 流程模板至少支持顺序审批、驳回、撤回、重新提交和审批意见。
- 需求审批通过后，可关联已有项目或创建新项目。
- 审批记录永久关联业务对象并进入审计日志。

### 4.7 工时与资源

- 成员在任务完成时填报实际工时。
- 系统展示成员可用工时、当前负荷和排期冲突。
- 资源视图支持按成员、部门、项目和时间段查看。
- 任务改期或新增分配造成冲突时提醒项目经理。

### 4.8 交付与客户验收

- 项目经理提交交付版本，并指定关联任务、文档及验收客户。
- 客户可以选择通过、驳回或要求修改，并填写验收意见。
- 驳回或要求修改时，原任务退回执行阶段。
- 系统保留每次交付版本、提交人、提交时间、文件清单和验收意见。
- 验收超期只催办，不自动通过。

### 4.9 合并与重复治理

管理员可以直接合并重复的项目、任务和需求。合并时：

- 评论、附件、工时、审批、风险、文档、交付和操作记录迁移到目标对象。
- 关联关系重新指向目标对象。
- 建议保留原编号和只读来源记录，标记“已合并”并跳转到目标对象。
- 合并撤销规则尚待确认。

### 4.10 风险与问题

- 记录风险标题、风险等级、描述、所属项目、负责人、状态和处理记录。
- 风险可关联项目、里程碑或任务。
- 风险分布纳入管理报表。
- 发生概率、影响程度、应对方案及高风险通知规则待确认。

### 4.11 文档管理

- 文档支持版本管理，保留上传人、上传时间、版本说明和关联业务对象。
- 客户只可访问明确授权且与其相关的文档。
- 支持文件存储服务集成。
- 在线预览、水印、下载控制和客户上传审核待确认。

### 4.12 预算与成本

- 手工维护项目预算、人工成本、其他费用和预算使用率。
- 第一版不对接财务系统。
- 当前需求为“所有人可以查看”，但外部客户的成本可见范围需在上线前确认。

### 4.13 通知与升级

通知渠道：站内消息、邮件、企业微信、Microsoft Teams。

关键通知事件包括需求提交、分派、审批、状态变化、任务临期、任务逾期、交付提交、客户验收和高风险事件。

逾期升级默认每 12 小时执行一级：

`负责人 → 项目经理 → 部门负责人 → 管理员`

### 4.14 报表

首期报表指标：

- 项目和任务完成率
- 任务逾期率
- 里程碑达成率
- 部门负荷
- 成员工时
- 风险分布
- 客户验收效率

报表需支持按时间、项目类型、项目、部门、负责人和客户筛选。

### 4.15 多端与国际化

- Web：完整管理能力。
- 移动端：创建需求、更新任务、填写工时、上传附件、客户验收。
- 桌面端：目标范围与 Web 一致，具体技术形态待定。
- 支持中文和英文；业务模板和用户录入内容是否双语不做自动翻译承诺。

### 4.16 账号、集成与部署

- 第一版由管理员创建账号，用户凭账号登录。
- 集成企业微信入口、通知能力和文件存储。
- 支持可选 OIDC 统一身份认证，并只映射管理员预先创建且启用的本地账号；具体身份提供方参数在部署时配置。
- 采用私有化部署。
- 客户只能看到与自己有关的需求、进度和文档。

## 5. 非功能需求

- 权限：服务端强制鉴权，不依赖页面隐藏；客户数据按关联关系隔离。
- 审计：关键修改、审批、合并、验收和权限操作可追溯。
- 可用性：中文与英文界面一致，常用操作适配移动端。
- 性能：按 500 人以上设计，具体并发量和数据容量待容量评估。
- 安全：密码安全存储、会话过期、登录失败限制、附件访问鉴权。
- 运维：支持配置备份、业务数据备份、日志查询和故障恢复。

## 6. 成功指标

- 项目、任务和里程碑状态覆盖率达到 95% 以上。
- 项目逾期事项能够在 12 小时周期内完成升级通知。
- 客户交付与验收记录可完整追溯。
- 管理者能够从报表直接识别逾期项目、资源冲突和高风险事项。
- 跨部门任务均有明确负责人、计划时间和实际结果。
