# MVP 与版本规划

## 1. 规划原则

第一版先打通“需求进入—审批—项目执行—交付验收—报表复盘”的完整闭环。多端均纳入产品目标，但以 Web 核心能力作为稳定基座。

## 2. MVP（建议）

### 2.1 必须上线

- 账号、组织、角色和权限
- 内外部用户隔离
- 内部项目、临时任务和可配置项目模板
- 项目、里程碑、任务、子任务
- 需求表单、待分派需求池、需求审批及转项目
- 看板与基础甘特图
- 项目经理跨部门分配成员
- 任务完成时填报工时
- 成员负荷、可用工时和排期冲突提示
- 文档上传、版本管理和业务关联
- 风险等级与风险台账
- 交付版本、客户验收、退回和历史记录
- 预算、人工成本、其他费用和使用率手工维护
- 站内消息、邮件通知及每 12 小时逾期升级
- 核心报表
- 操作审计
- 中文与英文界面
- 私有化部署、备份和基础运维能力

### 2.2 MVP 移动端

- 创建和查看需求
- 查看、更新任务
- 填写完成工时
- 上传附件
- 查看通知
- 客户验收

### 2.3 MVP 桌面端

建议第一阶段使用响应式 Web 或受控 Web 容器，待通知、文件和系统集成需求稳定后再评估原生桌面能力。

## 3. V1.1 集成与效率

- 邮件自动转需求
- 企业微信入口、通知及组织同步
- Microsoft Teams 通知
- 外部文件存储适配器
- 高级甘特图：依赖、关键路径、基线和拖拽排期
- 自定义报表与导出
- 更细粒度文档下载和水印控制

## 4. V1.2 企业治理

- 统一身份认证（OIDC/SAML/LDAP/AD，按企业环境选型）
- 流程与审批设计器增强
- 工作日历、节假日和多部门日历
- 预算预警和成本分析
- 合并撤销或合并纠错工具
- 数据归档、保留周期和审计导出

## 5. 暂不纳入首期

- 财务系统对接
- 自动确认客户验收
- 自动翻译用户录入内容
- 未确认的设备、会议室等非人员资源管理

## 6. MVP 验收主场景

1. 外部客户提交需求，只能查看自己的数据。
2. 无项目归属的邮件需求进入待分派需求池。
3. 需求根据项目类型走审批，审批后关联已有项目或创建新项目。
4. 项目经理跨部门分配任务，系统识别人员负荷和排期冲突。
5. 成员完成任务时填报工时，里程碑和项目进度自动汇总。
6. 项目经理提交交付版本，客户通过、驳回或要求修改。
7. 驳回后原任务退回，历史交付版本和验收意见不丢失。
8. 任务逾期每 12 小时逐级升级。
9. 管理员合并重复需求、任务或项目，业务内容正确迁移且可追溯。
10. 管理层查看完成率、逾期率、里程碑、负荷、工时、风险和验收报表。
