# 待确认事项与默认假设

本文件集中记录尚未由业务方明确决定、但会影响范围、权限或架构的事项。进入原型和详细设计前，应逐项确认。

## P0：上线前必须确认

| 编号 | 事项 | 当前默认假设/建议 |
|---|---|---|
| Q-01 | 是否增加独立的“客户交付项目”类型 | 首期先以内部项目承接客户需求；建议增加客户交付类型以隔离流程和报表 |
| Q-02 | 外部客户能否查看预算、人工成本和其他费用 | 内部用户可见；客户仅看经授权的预算摘要，不看人工成本和内部费用 |
| Q-03 | 项目经理“所有作业”的边界 | 可管理本项目作业，但不能代替客户正常验收 |
| Q-04 | 合并后的来源对象是否保留 | 保留只读记录、原编号和跳转关系，不直接删除 |
| Q-05 | 合并是否支持撤销 | MVP 不提供一键撤销，但保留完整映射，管理员可执行受控纠错 |
| Q-06 | 客户账号如何创建和绑定客户组织 | 由管理员创建并绑定客户组织、联系人和可访问项目 |
| Q-07 | 密码策略和账号生命周期 | 管理员创建、首次登录强制改密，支持禁用和密码重置 |

## P1：详细设计前确认

| 编号 | 事项 | 当前默认假设/建议 |
|---|---|---|
| Q-08 | 甘特图高级能力 | MVP 只读基础甘特图；V1.1 增加依赖、关键路径、基线和拖拽 |
| Q-09 | 工作日历 | MVP 使用统一企业工作日历，排除周末并支持维护节假日 |
| Q-10 | 临时任务是否必须属于项目 | 允许独立存在，可后续转入或合并至项目 |
| Q-11 | 风险字段 | 在风险等级之外增加概率、影响、应对方案、截止时间和升级规则 |
| Q-12 | 文档控制 | 支持在线预览、下载权限、水印及客户上传审核 |
| Q-13 | 工时是否需要审批 | 默认无需单独审批，由项目经理在项目范围内核查 |
| Q-14 | 项目预算维护权限 | 项目经理与管理员可维护，其他内部用户只读 |
| Q-15 | 审批设计器复杂度 | MVP 支持顺序审批；会签、或签、条件分支后续增强 |

## P2：技术选型和容量确认

| 编号 | 事项 | 当前默认假设/建议 |
|---|---|---|
| Q-16 | 峰值并发用户数 | 在架构设计前通过企业使用时段估算 |
| Q-17 | 同时进行的项目数与单项目任务上限 | 暂按企业级分页、异步报表和归档机制设计 |
| Q-18 | 单文件大小、文件类型和保留周期 | 由存储容量、安全策略和客户交付要求决定 |
| Q-19 | 桌面端技术形态 | 先使用响应式 Web/受控容器，再评估原生桌面应用 |
| Q-20 | 移动端技术形态 | 根据企业设备策略选择原生、跨平台或企业微信应用 |
| Q-21 | Teams 集成范围 | 首期仅通知；交互式卡片和任务操作后续评估 |
| Q-22 | 企业微信集成范围 | 首期入口与通知；组织同步在后续版本加入 |
| Q-23 | 文件存储产品 | 通过存储适配器接入企业选定产品，避免业务代码绑定单一厂商 |
