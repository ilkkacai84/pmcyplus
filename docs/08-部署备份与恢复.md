# 部署、备份与恢复

## 生产部署检查

1. 复制 `.env.example` 为 `.env`，替换数据库、初始管理员及所有集成密钥。
2. 执行 `docker compose config`，确认变量解析和服务依赖正确。
3. 执行 `docker compose up -d --build`，等待 MySQL、后端和前端健康检查通过。
4. 访问 `/actuator/health` 确认后端为 `UP`，再完成一次登录和核心业务冒烟测试。
5. 验证 `mysql_data` 与 `file_data` 两个命名卷均存在，并将 Docker 标准输出接入企业日志平台。

## 备份

在项目根目录执行：

```bash
./scripts/backup.sh /secure/backup/project-management
```

脚本同时生成 MySQL 逻辑备份和文档文件归档。生产环境应由调度平台定时执行，并将结果复制到独立、加密且有保留策略的存储；必须监控脚本退出码和文件大小。

## 恢复演练

恢复会覆盖目标环境数据，应先停止业务流量，并在隔离环境验证备份：

```bash
gzip -dc project-management-YYYYMMDD-HHMMSS.sql.gz \
  | docker compose exec -T mysql sh -c 'exec mysql -uroot -p"$MYSQL_ROOT_PASSWORD" "$MYSQL_DATABASE"'

docker compose exec -T backend tar -xzf - -C /app/data \
  < project-files-YYYYMMDD-HHMMSS.tar.gz
```

恢复后重启后端，检查 Flyway 版本、`/actuator/health`、账号登录、项目列表和文档下载。至少按企业恢复目标定期执行一次完整恢复演练；未经确认不要在生产数据库直接执行恢复命令。
